# Goldfish preimplementation review: data quality

Date: 2026-11-05. Scope: `docs/stage12-executable-spec.md`, `biosynvia/preparation.py`, v3 CSV/SQLite/manifest/dictionary, and bounded quality/EDA/unique-value evidence reads. Read-only SQL aggregates; no fitting, implementation, source modification, new broad EDA, or assay validation. This agent review assesses engineering decisions and evidence, not scientific assay validity. Karpathy review guidelines were applied to keep recommendations explicit and narrow.

Eight prioritized actionable findings follow. These are corrections/clarifications to make concrete in Stage 1/2 implementation; several are already required by the executable specification.

1. **P1 — The strict Status rule eliminates the existing eight-field core everywhere.** Evidence: `biosynvia/preparation.py:72,95,231–233`; `data/processed/v3/feature_lineage.csv` and SQLite `feature_lineage`. V3 labels **4,897** absent-Status rows `usable_for_inspection`, including **4,158** ProcessParameters field rows. Each of pH, dissolved O2, and temperature has **378/378** rows with `source_status=not_provided`. Thus requiring all original eight core fields while excluding unknown Status gives **0/378 complete assays**, regardless of the 1/5/15-minute freshness threshold. V3's **339** complete assays and **333** inspection candidates cannot be carried into the strict scenario. Recommendation: retain literal raw Status/column presence separately; absent is unknown and blocked. Report original-eight strict completeness as zero. Define a separate, explicit status-bearing five-field scenario (CO2, transmission, reflection, conductivity, permittivity) if justified for the split proposal, disclose its changed denominator and supported-input selection effect, and keep all input/scientific approvals false. Do not silently replace the original core or call absent Status Ok.

2. **P1 — One priority reason cannot represent independent quality evidence.** Evidence: `biosynvia/preparation.py:88–101` uses a mutually exclusive chain (duplicate, stale, Status, invalid, inactive-zero). V3 contains **437** stale feature rows, **554** Status-rejected rows (504 `Warning Active`, 50 null Status), and **880** inactive-derived-zero rows, but those reason counts are not independent flag prevalence. Recommendation: compute duplicate/invalid/stale/status-unknown/status-warning/past-only inactive-zero flags independently, then derive scenario eligibility from their conjunction. Preserve a reason list for inspection, with no flag inferred false merely because another rejection occurred. Test overlap explicitly (for example, stale plus Warning plus inactive zero). Define inactive-zero from the available past prefix only and avoid diagnosing a later re-zeroed value as inactive from the value alone. All selected v3 source values are finite/non-null; retain this negative finding and test synthetic invalid/nonfinite cases instead of claiming observed assay-cutoff invalid values.

3. **P1 — Freeze the distinction between six recorded target zeros and 214 medium blanks.** Evidence: `reports/quality-review/zero_source_cells.csv`, `recorded_zero_vcd.csv`, `report.md`; `reports/eda/assay_comparison_summary.csv`; `data/processed/v3/preparation_manifest.json`. There are **378** recorded VCD means, **372** positive and **6** numeric zeros: EXP002 R02 at 209.5 h, and EXP011 R02 at 148.5, 162.5, 171, 186, and 195 h. The **214** raw-medium blanks become aligned zeros (Glucose 135, Lactate 51, Ammonium 28); they are not observed zero measurements. Recommendation: retain all assays and source cell types/coordinates; separate positive-only and recorded-zero-inclusive proposed masks from scientific approval. Enforce original blank → missing and original numeric zero → zero in CSV and SQLite round trips. Sensor Ok and zero SEM must never approve an assay or imply exact certainty. The source report's detection/rounding/QC interpretation remains unresolved.

4. **P1 — Preserve actual workbook coordinates before dropping or joining rows.** Evidence: `biosynvia/preparation.py:71,182–187,195–197`; `data/processed/v3/original_offline.csv` has workbook/hash but no offline sheet/cell coordinates. `load_sheet` drops entirely blank rows and `source_row` is reconstructed from position; that method would shift sensor coordinates if internal blank rows exist (a code-level risk, not an asserted observed defect). Recommendation: capture worksheet row number and column letters directly during workbook iteration before any filtering; carry separate cell-analysis and medium-analysis coordinate maps through the outer join. Store raw value/type and numeric parsed value distinctly, and reconcile v3 IDs using experiment/reactor/time keys rather than assuming reconstructed row position. Verify the six documented B cells against their saved coordinates and retain every original assay field, including SEMs as forbidden inputs.

5. **P2 — EXP004 source duplicates exist although none are selected at assay cutoffs.** Evidence: `data/processed/v3/source_issues.json`: both reactors' CO2/Turbidity/Permittivity streams have 240 involved rows each and ProcessParameters 120 each (**8 streams; 1,680 involved source rows**). Read-only aggregation of v3 lineage finds **0** `duplicate_source_time_requires_review` rows and no selected candidate JSON. Recommendation: preserve competing rows/cells in a source-level collision artifact as well as a selected-observation duplicate flag; do not erase source duplicates because no current assay cutoff selects them. Report stream-level collision prevalence separately from assay-level impact. Never choose the last duplicate as a valid measurement by stable-sort order; explicitly test conflicting and identical candidate values. Duplicate counts must exclude invalid/null time values rather than treating repeated NaNs as true timestamp collisions.

6. **P2 — Freshness sensitivity needs raw per-stream cadence, not aligned cadence or only assay ages.** Evidence: `reports/quality-review/stream_profiles.csv`, `assay_stream_support.csv`, `report.md`; `data/processed/v3/feature_lineage.csv`. Current exhaustive stream profiles cover only EXP002/EXP011. EXP011 R02 aligned data end at 67.133333 h while original feed ends at 67.139444 h and other streams continue near 195 h; nine assays occur after the aligned endpoint. Recommendation: calculate positive adjacent-time deltas from finite, sorted unique raw timestamps for every stream, reporting duplicate/backward/invalid time counts separately. Summarize actual median/quantiles/max gaps and assay-level eligibility for 1/5/15-minute scenarios using one documented boundary tolerance. Derive each scenario from the same latest prior raw row, without target values/correlations or carry-forward beyond its age allowance. Preserve feed's loss of support separately from continuing sensor families; logging end is not evidence feed stopped.

7. **P2 — The v3 dictionary is insufficient for defensible field eligibility.** Evidence: `data/processed/v3/feature_dictionary.csv` has 40 sensor IDs but only a blanket `header_only_pending_review` unit status and no sheet/status/provenance or offline entries; `biosynvia/preparation.py:216–218` overwrites evidence per field. `reports/eda/field_dictionary.csv` extracts parenthesized text, including frequency qualifiers. Recommendation: preserve all source/sheet/header variants, modality, Status presence, unresolved semantics, proposed family and eligibility reason; include offline fields as prohibited predictors and IDs/mode/time as context. Distinguish quantity, unit text, and frequency qualifier: e.g., `C (300kHz)` supplies a frequency but does not verify C's unit; `Fitting Quality (Cole fit R2)` is a fit description, not a physical unit. Do not infer missing units, approve fitted channels from Ok alone, or globally eliminate fields based on all-run associations.

8. **P2 — Sample effects must be a cross-tabulated scenario result, not a single candidate count.** Evidence: `data/processed/v3/preparation_manifest.json` and SQLite `processed_candidates`: **378** assay rows in **24 reactors/12 paired experiments**, **339** v3 eight-core complete rows, **333** positive-target inspection rows; all six recorded zeros have v3 core completeness. Recommendation: report target-mask counts before quality filtering, per-family strict-status/freshness completeness, and joint target/input counts by reactor, experiment and mode. Keep strict-availability unknowns blocked as a separately labeled scenario; do not drop its zero coverage from the report. For proposed splits, disclose both reactors' coverage and the fixed target-blind core denominator used for minimum-coverage ranking. Preserve 12 as the experiment-group count and never count 274,781 aligned sensor timestamps or SEMs as independent outcome samples. List exclusions and common support so input-family comparisons cannot inherit different target populations silently.

## Verification evidence and limits

The numerical counts above were obtained by bounded stdlib `sqlite3` queries against `data/processed/v3/biosynvia.sqlite` opened with `mode=ro`, and bounded reads of saved CSV/JSON evidence. SQL grouped `feature_lineage` by reason/Status, counted absent-Status core fields, counted duplicate reasons, and aggregated `processed_candidates` by experiment and recorded-zero target. No model or target-correlation procedure was run. Raw status semantics, assay validity/detection limits, source export algorithm, rights/retrieval constraints, and result-availability timing remain unresolved scientific/provenance questions. Existing reports' claims about numeric Excel cell types were reviewed as saved evidence; this review did not independently validate an assay.
