Accepted correction supplied for this review: absent process Status makes strict eight-core coverage zero; a separately named five-status-bearing-core coverage is proposed solely for target-blind split ranking, with no feature approval implied. The following findings account for that correction and do not ask to relax unknown-status handling.

1. **P1 — Freeze the full producer/input closure before v4 execution.** The v3 manifest hashes only `preparation.py`, although it imports `inventory_archive` from `.source`; it provides no interpreter/dependency versions, exact command, configuration bytes, or producer snapshot location. The specification requires these to resolve but does not define the concrete record. Require an immutable producer snapshot (all executed local modules or a resolvable clean revision plus patch), hashes of the v3 manifest and each consumed v3 artifact, raw archive and workbook-member hashes, contract/spec hashes, exact command and working directory, Python/package versions, and a reproduction instruction. Verify all consumed v3 hashes before processing; test altered source, v3 artifact, config, and producer inputs separately.

2. **P1 — Preserve physical worksheet coordinates before filtering and merging.** `load_sheet` drops wholly blank rows, then `snapshot_stream` assigns `source_row = arange + 2`; an internal blank row would make downstream coordinates incorrect. `combine_original_assays` merges/sorts without retaining original assay row/cell coordinates. V4 must enumerate actual Excel rows and columns while reading, before dropping rows or sorting, and keep separate cell/medium assay origins, including blank and zero cells. Identify lineage by archive member, workbook hash, sheet, physical cell/range, original header and raw value; store time-cell and Status-cell coordinates and duplicate alternatives too. Test an internal blank row, reordered assay times, unequal modality times, and duplicate timestamps against exact expected cell addresses.

3. **P1 — Make split ranking executable and independent of assay outcomes.** The spec leaves “reactor core coverage” denominator, ranking window, scenario, and aggregation undefined. In its next revision, explicitly name strict-eight coverage and the proposed five-status-bearing ranking coverage, define the five field IDs, quality/age scenario, fixed observation grid or other target-independent denominator, time interval, minimum-of-two-reactors calculation, and numeric tie handling. If assay timestamps define the denominator, explicitly justify and freeze that dependency; never derive it from a positive-target mask or missing-target filtering. Persist every experiment/reactor score and ranking reason, then test permutations, tied scores, target zero/null/value mutations, and paired/disjoint folds using known expected winners.

4. **P2 — Define exact reproduction separately for stable data and volatile metadata.** Timestamps, absolute backup paths, dataframe memory measurements, CSV serialization, and SQLite bytes in the existing preparation output make “exact reproduction” ambiguous. Specify which artifacts must reproduce byte-for-byte and which require canonical logical equivalence; define row/column order, null/boolean/float encoding, JSON serialization and SQLite table/schema comparison. Keep timestamps and local paths outside stable content digests or document their expected variability. Test two fresh runs with identical inputs and compare the declared stable hashes plus canonical table contents, including zeros, nulls and duplicate candidates.

5. **P1 — Make validation a mandatory promotion gate with failure-injection tests.** Existing `prepare` writes to `.incomplete` and renames after checking only the original archive hash; it does not recheck the backup after use or validate CSV/SQLite agreement and manifest completeness before promotion. The spec's internal-validation requirement should enumerate: source and backup before/after hashes, consumed-input hashes, required artifact inventory, schema/keys/counts, lineage references, CSV/SQLite logical equality, split invariants and all artifact digests. Write the final manifest only after files/connections close, validate it before atomic same-filesystem promotion, and retain `.incomplete` on every failure. Tests should inject a mid-write error, backup/input mutation, missing artifact, corrupted artifact and validation failure, asserting that no final directory appears and existing versions are untouched. Record tests actually executed and make required checks fail rather than silently skip when dependencies are unavailable; the current preparation suite skips wholesale without pandas.

Disposition: five actionable engineering clarifications for the revised specification and implementation acceptance checks. No scientific approval inferred; no code or data modified by this review.
